# F-01 设计 token 与字体

## 目标

把视觉规范里的颜色、圆角、阴影、动效时长和字体落成一份全站 token。新版页面和组件只通过这份 token 取值。

## 背景

- 规范：`refactor/specs/01-visual.md` 第 2–5 节，`02-motion.md` 第 2 节（时长与缓动）。
- 试点有一份旧 token：`docs/preview/ui/tokens.css`（`--hg-thread`、`--motion-*` 等），命名和新规范不同。以新规范为准；试点用到的旧名字先保留为别名，NV-04 迁完试点后删除。
- 旧版页面用 VitePress 默认主题的 `--vp-*` 变量，本任务不改变旧版外观。VitePress 的暗色模式是 `html.dark` 类。
- 国内访问 Google Fonts 不稳定，字体必须自托管（`@fontsource`）。

## 要做的事

1. 新建 `docs/.vitepress/theme/v2/tokens.css`：01 第 2 节的中性色、语义色、分类色、代码区颜色（亮暗两套），圆角、描边、阴影、点阵背景，02 的时长和缓动 token，`prefers-reduced-motion` 处理。
2. 区域主题：`[data-zone="novice|forge|trial"]` 覆盖强调色、底色和点阵（01 第 5 节）。
3. 安装 `@fontsource/space-grotesk` 和 `@fontsource/jetbrains-mono`，`package.json` 写精确版本；只引入用到的字重和 latin 子集；中文用系统字体栈。在完成记录里写明新增的字体文件体积。
4. 在主题入口引入 tokens.css。新 token 只定义变量，不给 `body`、`h1` 等元素加样式，旧版页面外观不变。
5. 顺手把 `package.json` 里 `esbuild` 的版本改成精确版本 `0.25.12`（09 第 3 节要求依赖固定版本）。
6. 预览页 `docs/preview/tokens/index.md`：色板、字体样张、圆角和阴影、三个区域主题、亮暗对比。

## 验收标准

- [ ] 01 第 2 节列出的每个 token 都已定义，亮色和暗色各一套
- [ ] 给容器设置 `data-zone` 后，三个区域主题的颜色正确
- [ ] 构建产物里没有对 fonts.googleapis.com 或其他外部字体服务的请求
- [ ] 旧版任意一章的外观和改动前一致（改动前后各截一张图对比）
- [ ] 预览页在桌面和 375px 宽度、亮色和暗色下都正常
- [ ] `npm run refactor:check`、`npm test`、`npm run docs:build` 全部通过

## 验证方式

- `npm run refactor:check`
- `npm test`
- `npm run docs:build`
- `npm run docs:dev` 后打开 `/preview/tokens/`，在浏览器里检查桌面和 375px 宽度、亮色和暗色
