# FG-05 2-5 一行 PyTorch 背后（kernel 与 trace）

## 目标

按关卡模板做出「2-5 一行 PyTorch 背后：kernel 与 trace」网页，读者学完能回答：torch 的一行代码启动了哪些 kernel？哪个最耗时？

## 背景

- 大纲条目：`forge-behind-pytorch`（推荐 Lv.13，约 30 分钟，需要真卡）。
- 硬件落点：kernel 启动开销；多个小 kernel 反复读写显存
- 核心交互：交互式 trace 浏览器（真实采集数据）+ 在实验室里采集自己的 trace
- 两条路线共用（`routes: shared`），不使用 RouteBlock，只生成一份 Notebook。
- 本关的实验室 Notebook 由 FG-LAB-05 编写；网页的「探索」各段和 Notebook 的「动手」各段一一对应。
- 本关没有 Agent 支线。

## 要做的事

1. 读大纲条目、`06-stage-template.md`、`05-writing.md`（铸造城语气：工程师之间的交流，简洁）、`03-interaction.md`；读上一关的页面和本关 Notebook 源 `notebooks/src/forge/behind-pytorch.md`。
2. 交互式 trace 浏览器做成本关 scenes 组件，读取档案馆里的真实 trace；R-02 之前用标注「示意」的样例数据。
3. 写 `docs/forge/behind-pytorch/index.md`：11 项骨架；挑战用 `LabCard`；Mission 的星级标准从 outline 的 `lab.stars` 读取。
4. 本关可视化放 `docs/forge/behind-pytorch/scenes/`。需要真实数据的地方从档案馆读取；还没有数据时用标注「示意」的数据，并在完成记录里列出，由 R-02 替换。
5. 正文里的实测数字一律引用档案条目；暂时没有的写「[待实测]」。
6. 新术语登记进 glossary（首次出现链接概念卡）。
7. 把 outline.json 里 `forge-behind-pytorch` 的 `status` 改成 `draft`，运行 `npm run outline:md`。
