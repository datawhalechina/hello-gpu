# FG-03 2-3 测得准（可信计时）

## 目标

按关卡模板做出「2-3 测得准：可信计时」网页，读者学完能回答：怎样测出可信的 kernel 耗时？

## 背景

- 大纲条目：`forge-trusted-timing`（推荐 Lv.12，约 30 分钟，需要真卡）。
- 硬件落点：异步启动、GPU 事件计时、预热、缓存冷热
- 核心交互：噪声模拟器 + 实验室：比较单次计时和多次统计，记录中位数和波动
- 两条路线共用（`routes: shared`），不使用 RouteBlock，只生成一份 Notebook。
- 本关的实验室 Notebook 由 FG-LAB-03 编写；网页的「探索」各段和 Notebook 的「动手」各段一一对应。
- 本关有 Agent 支线（06 第 3 节第 7 项）。

## 要做的事

1. 读大纲条目、`06-stage-template.md`、`05-writing.md`（铸造城语气：工程师之间的交流，简洁）、`03-interaction.md`；读上一关的页面和本关 Notebook 源 `notebooks/src/forge/trusted-timing.md`。
2. 噪声模拟器做成本关 scenes 组件：随机噪声参数可调，对比单次计时和多次统计的结论。
3. 写 `docs/forge/trusted-timing/index.md`：11 项骨架；挑战用 `LabCard`；Mission 的星级标准从 outline 的 `lab.stars` 读取。
4. 本关可视化放 `docs/forge/trusted-timing/scenes/`。需要真实数据的地方从档案馆读取；还没有数据时用标注「示意」的数据，并在完成记录里列出，由 R-01 替换。
5. 正文里的实测数字一律引用档案条目；暂时没有的写「[待实测]」。
6. 新术语登记进 glossary（首次出现链接概念卡）。
7. 把 outline.json 里 `forge-trusted-timing` 的 `status` 改成 `draft`，运行 `npm run outline:md`。
