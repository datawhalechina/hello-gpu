# FG-13 2-13 可靠的优化闭环（候选、裁决与停止）

## 目标

按关卡模板做出「2-13 可靠的优化闭环：候选、裁决与停止」网页，读者学完能回答：Agent 怎么管理候选？什么时候接受，什么时候停？

## 背景

- 大纲条目：`forge-reliable-loop`（推荐 Lv.19，约 45 分钟，需要真卡）。
- 硬件落点：测量噪声、配对 A/B、多形状校验
- 核心交互：逐步执行候选闭环；识破噪声范围内的「加速」和只测了一个形状的「正确」
- 两条路线共用（`routes: shared`），不使用 RouteBlock，只生成一份 Notebook。
- 本关的实验室 Notebook 由 FG-LAB-13 编写；网页的「探索」各段和 Notebook 的「动手」各段一一对应。
- 本关没有 Agent 支线。

## 要做的事

1. 读大纲条目、`06-stage-template.md`、`05-writing.md`（铸造城语气：工程师之间的交流，简洁）、`03-interaction.md`；读上一关的页面和本关 Notebook 源 `notebooks/src/forge/reliable-loop.md`。
2. 「识破」环节：噪声范围内的「加速」和只测了一个形状的「正确」，选对发「识破假加速」徽章。
3. 写 `docs/forge/reliable-loop/index.md`：11 项骨架；挑战用 `LabCard`；Mission 的星级标准从 outline 的 `lab.stars` 读取。
4. 本关可视化放 `docs/forge/reliable-loop/scenes/`。需要真实数据的地方从档案馆读取；还没有数据时用标注「示意」的数据，并在完成记录里列出，由 R-04 替换。
5. 正文里的实测数字一律引用档案条目；暂时没有的写「[待实测]」。
6. 新术语登记进 glossary（首次出现链接概念卡）。
7. 把 outline.json 里 `forge-reliable-loop` 的 `status` 改成 `draft`，运行 `npm run outline:md`。
