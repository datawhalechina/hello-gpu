# FG-12 2-12 Agent 的工具箱（工具封装与守门）

## 目标

按关卡模板做出「2-12 Agent 的工具箱：工具封装与守门」网页，读者学完能回答：怎样把编译、校验、计时、分析封装成 Agent 能用的工具？

## 背景

- 大纲条目：`forge-agent-tools`（推荐 Lv.19，约 35 分钟，需要真卡）。
- 硬件落点：工具在真卡上运行；失败时要返回结构化的原因
- 核心交互：逐个调用工具，看失败时 Agent 拿到什么反馈（Agent 修改的是读者所选路线的源码）
- 两条路线共用（`routes: shared`），不使用 RouteBlock，只生成一份 Notebook。
- 本关的实验室 Notebook 由 FG-LAB-12 编写；网页的「探索」各段和 Notebook 的「动手」各段一一对应。
- 本关没有 Agent 支线。

## 要做的事

1. 读大纲条目、`06-stage-template.md`、`05-writing.md`（铸造城语气：工程师之间的交流，简洁）、`03-interaction.md`；读上一关的页面和本关 Notebook 源 `notebooks/src/forge/agent-tools.md`。
2. 用 AgentConsole 回放一段真实的工具调用轨迹（R-04 之前用示意轨迹）。
3. 写 `docs/forge/agent-tools/index.md`：11 项骨架；挑战用 `LabCard`；Mission 的星级标准从 outline 的 `lab.stars` 读取。
4. 本关可视化放 `docs/forge/agent-tools/scenes/`。需要真实数据的地方从档案馆读取；还没有数据时用标注「示意」的数据，并在完成记录里列出，由 R-04 替换。
5. 正文里的实测数字一律引用档案条目；暂时没有的写「[待实测]」。
6. 新术语登记进 glossary（首次出现链接概念卡）。
7. 把 outline.json 里 `forge-agent-tools` 的 `status` 改成 `draft`，运行 `npm run outline:md`。
