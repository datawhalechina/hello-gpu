# Hello GPU 重构方案 v2

> 状态：已和作者对齐，进入执行。日期：2026-11-08。分支：`refactor/v2`。
> 本文件说明「做成什么样、为什么这样做、按什么顺序做」。怎么做见 `refactor/specs/`，做什么见 `refactor/tasks/`，会话怎么接活见 `refactor/README.md`。

## 1. 一句话

把 Hello GPU 从「按章节读的文档」改成「按关卡玩的教程」：新手在浏览器里用 GPU 模拟器闯关入门，进阶读者在真卡上用实验室 Notebook 闯关，三类读者从同一张地图出发，按自己的水平选起点。

## 2. 已经确定的决定

| 方面 | 决定 |
| --- | --- |
| 读者 | 三类：零基础、会 PyTorch 的算法工程师、已经会写算子的工程师 |
| 结构 | 前言 + 定级测试 + 三个区域；区域只标推荐等级，从不上锁；经验值累积升级，Lv 不封顶，每 300 XP 升一级 |
| 区域 | RPG 主题：新手村（Lv.1–10，浏览器模拟器）→ 铸造城（Lv.10–20，云上或本地真卡）→ 试炼场（Lv.20–30，真卡）。无尽之塔（进阶优化方法、算子库）本版不做 |
| 编排 | 硬件全景先行，之后软件和硬件交替深入；每关从一个具体问题开始 |
| 写法与路线 | 新手村共用，代码可选 HIP 风格或 Python 风格（都是线程视角）；从铸造城开始分 HIP 路线和 Triton 路线，题目、硬件讲解和实测数据共用 |
| Agent | 每个区域都有 Agent 内容：新手村 ReAct 入门 → 铸造城可靠的单 Agent → 试炼场多 Agent 与 GEAK（只讲单 kernel 优化流程） |
| 副本 | 可选的额外练习，以自研题为主；外部题（如 LeetGPU）只链接原题、写原创题解 |
| 后端 | 不做。进度存在读者浏览器里，用导出 / 导入换设备；不做登录和排行榜 |
| 范围 | 只讲算子优化，不涉及推理框架。「端到端」只到把算子接回 PyTorch 模型、测一次前向 |
| 模拟器 | 浏览器里的 JS 教学模拟器，按需要分 L1–L4 四层；借鉴 mlsys-simulator 的 GPU 模拟工程方法，不使用它的推理服务沙盘 |
| 视觉 | 精致科技风 + 有亲和力的吉祥物「小核」；区域换装；关卡页是单列长页 + 顶部进度 |
| 真卡关卡 | 网页是关卡，Notebook 是实验室，两者用「通关码」连起来（第 5.2 节） |
| Notebook | 参考 d2l：一个教学包、和网页同构的小节、一份源文件生成两条路线的 Notebook（第 6 节） |
| 旧版 | 保留原有 URL 和 Notebook 位置，新增 `/v1/` 目录页 |
| 生产方式 | 以 AI 辅助开发（vibe coding）为主：一位执行者用 AI 编码助手按顺序做任务；每段工作一个分支、一个到 `refactor/v2` 的 PR，作者在 6 个关口审查 PR，问题在 PR 里沟通，合并即验收通过 |

## 3. 重构完成后的样子

**零基础读者**打开首页，点「开始冒险」，进入新手村第一关「一千道加法」。每关的节奏相同：读一句任务，先猜一个结果，动手拖滑块或改一行代码，马上看到线程小机器人怎么干活，再读原理、拿星。十四关之后，读者能看懂 GPU 怎么执行一个 kernel，能写出正确的下标和边界检查，知道合并访存、LDS、归约、计时为什么重要，还亲手补全了一个在模拟器上自动调参的 ReAct Agent。全程只需要浏览器。

**会 PyTorch 的工程师**先做定级测试，被推荐到铸造城（前面的关卡标为「已豁免」，以后可以回去补星）。在区域入口选 HIP 或 Triton 路线。每关在网页上看任务、先猜、看原理和可视化，然后点「打开实验室」，在云平台或本地的 Notebook 里写 kernel、校验、计时，最后一个单元打印通关链接。点回网页，星级按本关规则算出来，读者自己的数字和参考数据画在同一张图上。没有 GPU 的读者可以选「观摩模式」，看档案馆里的真实运行记录。区域 Boss 是用自己写的算子打败 torch，再让 Agent 复现。

**会写算子的工程师**直接去试炼场：读 ISA、用 rocprofv3 计数器找瓶颈、调占用率、做 GEMM 分块和矩阵核心、写 Attention，最后剖析并复现 GEAK。每个结论都附实测证据。

所有读者都能在「我的成长」看到等级、星、徽章和图鉴，在「冒险者手册」查术语和比喻，随时导出存档。

## 5. 三个区域怎么闯关

### 5.1 新手村：模拟器关卡

- 每关按「任务 → 先猜 → 动手 → 即时反馈 → 原理 → 星级」展开（`03-interaction.md`）。
- 动手部分跑在浏览器模拟器上。模拟器只输出事件流，动画、判星、单测都读同一份事件流，所以判星是确定的、可测试的（`08-simulator.md`）。
- 模拟器分四层，按关卡需要建设：L1 逻辑（谁算哪个数，试点已完成）、L2 锁步执行（wave、掩码、barrier、竞争）、L3 访存（cache line「车次」、bank 冲突）、L4 示意计时与占用率。L3、L4 的数字一律标「模拟」。
- 星级由每关的 `challenge.ts` 判定：★1 结果正确，★2 达到效率目标，★3 最优或额外挑战。在挑战里看答案，本关最高 2 星。

### 5.2 铸造城和试炼场：网页关卡 + 实验室

Notebook 在别处运行（云平台或读者本机），网页无法直接拿到结果。没有后端时，我们用「通关码」把两边连起来：

```text
网页关卡                                     实验室 Notebook（云上或本地）
──────────                                   ─────────────────────────
任务 · 先猜 · 原理 · 可视化
LabCard「打开实验室」  ───────────────────▶  准备 → 动手 → 挑战
                                             hg.check 多形状校验
                                             hg.bench 可信计时
                                             hg.compare 对比 torch 和峰值
                                             hg.submit() 打印通关链接 / 通关码
LabCard 读取 #lab=… 或粘贴通关码  ◀────────  （读者点链接或复制）
按本关规则重新算星，画出读者的数字
```

- **通关码**：凭证 JSON（关卡 id、路线、设备、环境、校验结果、测量数字）压缩后 base64url 编码，前缀 `HGPU1.`。网页只信任数字，星级按 `outline.json` 里本关的 `lab.stars` 规则重新计算（`07-notebook.md` 第 8、9 节）。
- **相对目标**：读者的卡可能是 RX 9070 XT、云上的 W7900D 或 Radeon 8060S，所以效率星只用相对值，例如「达到你这张卡实测峰值带宽的 60%」「比同一张卡上的 torch 快」。峰值在 2-4 由读者自己测出。
- **没有排行榜**：凭证可以伪造，但只影响读者自己的本地进度。
- **观摩模式**：没有 GPU 的读者回放档案馆里的真实运行记录，完成关卡得经验值，不得星；以后有了 GPU 可以再导入通关码补星。
- **我的 GPU 卡片**：2-1 运行 `hg.device_card()` 得到导入码，导入后新手村 1-2 的全景图和 2-4 的 Roofline 换成读者真机的参数。
- **实验档案馆**：作者在真卡上跑出的参考记录存在 `docs/lab/data/`。正文里的实测数字只能来自这里，观摩模式也回放这里的数据。

### 5.3 Agent 主线

| 区域 | 关卡 | 读者做什么 |
| --- | --- | --- |
| 新手村 | 1-13、1-14、支线 1-4 / 1-8 / 1-11 | 先自己当 Agent 选下一步，再补全 ReAct 循环的三个空，让它在模拟器上自动调参；可选接入自己的大模型 API Key |
| 铸造城 | 2-12、2-13、支线 2-3 / 2-9 | 把编译、校验、计时封装成工具，搭候选 → 裁决 → 停止的可靠闭环，识破噪声里的「假加速」 |
| 试炼场 | 3-11、3-12、支线 3-3 / 3-7 | 拆成多角色、确定性编排、记忆；在容器里剖析并复现 GEAK |

需要大模型的 Notebook 都提供不调用大模型的回放路径，没有 API Key 也能学完。

### 5.4 副本

挂在每个区域旁边的可选练习，不占主线，每题 50–150 XP。新手村副本跑在模拟器上，铸造城和试炼场副本用实验室 + 通关码。外部题库只链接：LeetGPU 为 CC BY-NC-ND 4.0，不能翻译或改编题面；GPU MODE reference-kernels 使用自定义许可证；GPU-Puzzles 为 MIT，可以改编并署名。

### 5.5 定级测试

三组题逐组作答，某组没达标就停下，推荐从这一组开始。答对的题对应的关卡标为「已豁免」，定级等级换算成经验值（例如 Lv.10 = 2700 XP），存档里标注来源「定级」。

## 6. Notebook 配套重构

目标是简单，并且让读者在网页和 Notebook 之间对得上号。参考 d2l 的三点做法：

1. **一个教学包**：每本 Notebook 开头 `import hello_gpu as hg`。编译、计时、校验、画图、交成绩都藏在包里，Notebook 里只留这一关要学的代码，每个代码单元不超过 15 行。
2. **和网页同构**：Notebook 的小节和网页关卡一一对应。

   | Notebook | 网页 |
   | --- | --- |
   | 标题单元（自动生成：关卡、路线、网页链接、环境） | 关卡头 |
   | 准备 | — |
   | 动手（1–3 段） | 探索（1–3 段） |
   | 挑战 | 挑战（LabCard） |
   | 交成绩 | LabCard 导入 |
   | 练习 | 深入一点 |

   先猜、原理讲解和概念卡只在网页上，Notebook 里用一句话加链接指回去。
3. **一份源文件，两条路线**：源文件是 `notebooks/src/<zone>/<slug>.md`，实现单元用 `route=hip` / `route=triton` 标记，`npm run nb:build` 生成 `<slug>-hip.ipynb` 和 `<slug>-triton.ipynb`（共用关卡只生成一份）。生成的 Notebook 提交进仓库、不带输出，读者在云平台上不需要任何构建步骤。

旧版 Notebook 留在 `notebooks/part*/` 原处，`hello_gpu` 的旧接口保持不变。细节见 `07-notebook.md`。

## 7. 技术架构

```text
数据      docs/course/outline.json   课程结构（唯一数据源）
          docs/course/glossary.json  术语与比喻      badges.json  徽章
          docs/course/hardware.json  硬件参数（附出处）
          docs/lab/data/             实验档案（真实测量）
             │
逻辑      docs/sim/                  模拟器（纯 TS：语法 → 锁步 → 访存 → 计时）
          docs/course/*.ts           进度、挑战状态、通关码、定级、Agent
             │
组件      docs/components/kit/       登记过的内容组件（Mission、Predict、Sandbox、RobotGrid、LabCard……）
             │
布局      docs/.vitepress/theme/v2/  HgLayout（通用页）、StageLayout（关卡）、DungeonLayout（副本）
             │
页面      docs/{novice,forge,trial}/<slug>/index.md  只写内容，元信息从 outline 读
```

- **站点**：继续用 VitePress 2 + Vue 3，新版页面用自定义布局，旧版页面保持默认主题。
- **进度**：`docs/course/progress.ts` 是纯函数，`storage.ts` 负责 localStorage、持久化申请、跨标签页同步和导出导入。所有组件通过 `useProgress()` 访问，服务端渲染阶段不读本地存储。
- **一致性检查**：`npm run refactor:check` 汇总任务文件、大纲、术语与徽章数据、关卡骨架和禁用词、Notebook、档案数据等检查，随任务逐步加入。
- **性能**：首屏 JS 压缩后不超过 200 KB；代码编辑器、模拟器 Worker、Pyodide 都按需加载。
- **字体**：Latin 字体用 `@fontsource` 自托管，中文用系统字体，不依赖 Google Fonts。

## 8. 阶段、关口与上线策略

| 阶段 | 内容 | 任务数 | 结束关口 |
| --- | --- | --- | --- |
| 0 基建 | token、路由、截图巡检、进度、吉祥物、布局、内容组件、奖励、关卡检查 | 16 | G-01 作者验收视觉与组件 |
| 1 新手村 | 模拟器 L1–L4、沙盒与可视化、14 关 + Boss、Agent、全局页面、定级测试、新手村副本、旧版入口与上线切换 | 41 | G-02 前 6 关试玩；G-03 新手村全区试玩 |
| 2 铸造城 | hello_gpu v2、通关码、Notebook 生成、档案馆、观摩模式、13 关 + Boss（网页与实验室）、真机验证、副本 | 44 | G-04 作者真卡试跑 |
| 3 试炼场 | 12 关 + Boss（网页与实验室）、真机验证、副本 | 32 | G-05 作者真卡试跑 |
| 4 收尾 | 全站巡检、文档更新、部署前检查 | 4 | G-06 上线验收与合并 |

**上线策略**：新手村完成并通过 G-03 后，就执行 M-01、M-02，让新版以「新手村 + 旧版其余内容」的形式先上线。地图上还没做的铸造城、试炼场关卡显示「建设中」，并链接旧版对应章节。之后每完成一关就多开放一关。这样读者能尽早用上新版，作者也能尽早拿到真实反馈。合并和部署始终由作者决定。

**节奏**：任务按 `order` 排队，执行者一个接一个做，提交到工作分支 `work/<下一个关口>`，这一段的草稿 PR 作者随时可看。到达作者验收关口时，`tasks:next` 会停下，执行者把 PR 转为待审查；作者在 PR 里提意见，执行者修改，作者合并 PR 即验收通过，GitHub Actions 自动把这段任务标为「已完成」，执行者继续下一段。需要真卡的 R 系列任务只在有 AMD GPU 的机器上出现。

## 9. 任务系统与看板

- 137 个任务，每个任务一个 Markdown 文件，放在 `refactor/tasks/`。frontmatter 记录编号、阶段、领域、状态、依赖、规模、是否需要 GPU、必读规范和产出；正文固定为目标、背景、要做的事、验收标准、验证方式、完成记录、验收记录。
- 编号前缀：F 基建、S 模拟器、P 全局页面、Q 定级测试、NV 新手村、A Agent、X 副本、L 实验室、FG / FG-LAB 铸造城网页 / 实验室、TR / TR-LAB 试炼场网页 / 实验室、R 真机验证与档案、M 上线、G 作者验收关口。
- 状态只用命令修改（`npm run tasks -- start / review / done / reopen / block`），每个任务提交并推送到当前工作分支；PR 上由 GitHub Actions 自动跑检查，PR 合并后自动标记验收通过。
- 网页看板 `/preview/board/` 直接读取任务文件：按状态分列、按阶段和领域筛选、显示下一步可做的任务和等作者处理的事项，可以复制固定提示词。
- 开工、验收的完整流程见 `refactor/README.md`。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 不同会话产出的风格、口吻不一致 | 九份规范先定好；每个任务列出必读规范；关卡任务要求先读上一关；`refactor:check` 自动查骨架、组件和禁用词；作者在 G-01、G-02、G-03 集中把关 |
| 编造硬件参数或实测数字 | 硬件参数集中在 `hardware.json` 并附出处；实测数字只能来自档案馆；查不到就写「[待实测]」，由真机任务替换 |
| 模拟结果被当成真实性能 | 模拟数字一律标「模拟」；每关末尾的证据卡说明数据来源；「深入一点」说明模拟器简化了什么 |
| 开发机没有 AMD GPU | 实验室任务拆成「编写」（任何机器）和「真机验证」（R 系列，`gpu: true`）；`tasks:next` 自动按机器过滤 |
| 读者浏览器清理数据，存档丢失 | 申请持久存储；「我的成长」提醒定期导出；存档码可以复制保存 |
| 代码编辑器和 Pyodide 拖慢页面 | 全部按需加载；构建产物检查首屏 JS；M-05 统计部署体积 |
| 云平台不支持一键打开 Notebook | L-06 逐个平台确认；不支持时提供下载和 GitHub 链接两种方式 |
| GEAK 版本变化、需要跳过权限运行 | 写 3-12 前重新核对官方 README；Notebook 只在容器里运行 GEAK |
| 外部题库许可证 | 只链接、写原创题解，不复制题面 |
| 作者验收成为瓶颈 | 普通任务不单独验收，随本段 PR 一起审查；只在 6 个关口停下等作者合并 PR |
| 旧版外部链接失效 | 旧版章节保留原 URL；新增 `/v1/` 目录页和新旧映射 |

## 11. 不做什么

- 不做登录、排行榜、云端同步等任何需要后端的功能。
- 不讲推理框架和推理服务（包括 GEAK 面向推理服务的端到端流程）。
- 本版不做无尽之塔。
- 不翻译、不改编外部题库的题面。
- 不在 Notebook 里安装依赖；环境由云平台或实验环境指南准备。
