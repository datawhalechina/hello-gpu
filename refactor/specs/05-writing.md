# 05 语言风格规范

全书的声音像一位耐心的学长在旁边陪你做实验：先说现象和目的，再给术语；句子短，说得具体，说的话都能验证。

## 1. 分区域的语气

| 区域 | 读者应该感到 | 语气 | 术语 | 代码 |
| --- | --- | --- | --- | --- |
| 新手村 | 「我能行」 | 口语化、鼓励，用第二人称「你」 | 每关新术语不超过 3 个，首次出现必须有大白话解释和概念卡 | 每段不超过 10 行 |
| 铸造城 | 「我在做真实的工程」 | 工程师之间的交流，简洁 | 可以直接用，首次出现链接概念卡 | 每段不超过 30 行，更长的折叠 |
| 试炼场 | 「我在逼近极限」 | 精确，引用一手资料 | 默认读者懂，附官方文档链接 | 不限长度，但要逐段解读 |

## 2. 句子与段落

- 句子以 25 字以内为主，不写三层以上的从句。
- 段落不超过 3 句；每屏至少有一个图、交互或代码块。
- 先结论后解释：每节第一句就是这节的结论。
- 主动语态，具体主语：写「线程 5 读取 c[5]」，不写「数据被读取」。
- 数字带单位和条件：「在 RX 9070 XT、ROCm 10.0、FP32、n = 2^24 下，有效带宽为 …… GB/s」。实测数字必须来自实验档案馆，并在旁边放 `EvidenceCard`。

## 3. 术语

- 统一译名放在 `docs/course/glossary.json`。首次出现写成「中文（English）」，之后只用一个叫法；同一个概念全站只有一个名字。
- 不翻译的术语也要登记：wavefront、lane、LDS、kernel、tile。
- 新手村禁止出现没有解释的缩写。
- 严格区分「模拟」和「实测」，这两个词不混用。

## 4. 比喻：芯片工坊城

全站只用一套比喻。需要新比喻时，先登记到 glossary 再用。

| 概念 | 比喻 |
| --- | --- |
| GPU 芯片 | 工坊城 |
| 计算单元 CU / WGP | 车间 |
| SIMD | 车间里的一条流水线 |
| kernel | 工作单（大家照着同一份做） |
| 线程 | 线程小机器人 |
| wavefront | 一起行动的小队（同一时刻做同一件事） |
| 线程块 block | 一组派到同一个车间的机器人 |
| grid | 这次派出的全部组 |
| 寄存器 | 机器人手边的工具台 |
| LDS | 车间里的共享货架 |
| 显存 | 城外的大仓库（显存格子） |
| cache line | 一车（一次成块搬运） |

比喻必须服务于一个具体机制，并紧接着说明它在哪里不成立（「比喻边界」）。例如：「线程像机器人，但它并不独占一条流水线。」

## 5. 禁用与慎用

| 不要写 | 改成 |
| --- | --- |
| 「显然」「众所周知」「很简单」 | 直接解释；读者觉得不显然时，这些词会伤人 |
| 「本节将介绍……」 | 直接给结论 |
| 「性能提升明显」 | 「耗时从 1.20 ms 降到 0.85 ms（减少 29%），条件是……」 |
| 「这个优化很重要」 | 说清对什么重要、重要多少 |
| 新手村里的术语串，如「VGPR 占用导致 occupancy 下降」 | 拆成几句，每个术语配概念卡；或者整句移到后面的区域 |
| 营销腔，如「史上最强」「一文搞定」 | 删掉 |
| AI 腔，如「让我们一起深入探索」「值得注意的是」「总而言之」「不仅……更……」「赋能」 | 删掉，直接说事（由 `refactor:check` 自动检查） |
| 大量网络梗 | 每关最多一处轻松表达 |

## 6. 改写示例

- 原文：「当我们手里有了一个能跑通的正确基线后，如何系统性地判断下一步值得改什么？」
- 铸造城版：「你的 vector add 已经算对了。下一步改哪里？改完是留还是退？这一关用三次小实验回答。」
- 新手村版：「10 个数，4 个机器人一组。要几组？多出来的机器人怎么办？先猜一猜，再拖动滑块看看。」

## 7. 排版

- 中英文之间加空格，数字和单位之间加空格；中文语境用全角标点。
- 代码、文件名、命令、API 名用行内代码格式。
- 关卡标题用「故事化名字 + 技术副标题」，例如「一起行动的小队：wavefront 与 SIMD」。
