# 03 交互规范

每个知识点都必须让读者「动手改变一个东西，并看到后果」。纯播放动画只能做补充，不能单独承担一个知识点。

## 1. 核心范式

1. **任务**：一句话说清目标，成败可以判定；用读者的话说，不出现新术语。
2. **先猜**：用选择、估值或排序让读者预测。猜错不扣分，猜对也不加分；只记录第一次锁定的答案，揭晓时对照「你刚才猜的是……」。
3. **动手**：每次只开放 1–3 个可调参数；默认值「能跑但不好」；随时可以重置。
4. **即时反馈**：参数变化在 100 ms 内给出可视化和一句话解读。出错时说明「哪里错、为什么、怎么改」，不只给红叉。
5. **原理**：这时才给术语和一句话定义，链接概念卡；细节放进「深入一点」。
6. **星级**：★1 结果正确，★2 达到效率目标，★3 最优或完成额外挑战。星级标准在关卡开头公示。

## 2. 交互密度

- 每关至少 1 个「先猜」和 1 个「动手」；新手村每关 4–6 个交互。
- 连续纯阅读不超过约 400 字（大约一屏半）。
- 一个交互只服务一个结论；两个结论就拆成两个交互。

## 3. 组件登记表

关卡只能使用登记过的组件。需要新的交互形式时，先在任务的「完成记录 → 待确认」里写明它服务哪个结论，由作者确认后再加入组件库并更新本表。

## 4. 反馈与容错

- **不惩罚**：猜错、运行出错都不扣经验值，可以无限重试。
- **提示阶梯**：失败 2 次给方向，4 次给具体位置，6 次允许看答案。在挑战里看答案，本关最高 2 星；探索环节看答案不影响星级。
- **错误信息**：写成「现象 + 原因 + 怎么改」；编译器或解析器原文放进折叠块。
- **自动保存**：每关的代码、参数和进度自动存到本地，刷新不丢。
- **随时可跳过**：每关都有「我已经会了，直接做挑战」的入口；先猜可以「跳过预测，直接看」。

## 5. 两种写法与两条路线

- **新手村**：所有代码同时提供 HIP 风格和 Python 风格（都是线程视角），全站记住读者的偏好。两种写法的内建名字一致（`blockIdx.x`、`threadIdx.x`），解析成同一棵语法树，结果和可视化完全相同。
- **铸造城、试炼场**：读者在区域入口选 HIP 路线或 Triton 路线，之后每关可切换。题目、硬件讲解、挑战目标、实测数据共用；实现部分用 `RouteBlock` 分开。同一关用哪条路线通关，星和经验值都一样。
- 写法偏好和路线偏好是两个独立设置。

## 6. 真卡关卡（实验室）的交互

铸造城和试炼场的动手部分在 Notebook 里完成，网页负责任务、先猜、原理、可视化和成绩：

1. 网页上的 `LabCard` 给出「打开实验室」（云平台链接、下载、GitHub 查看三种方式）。
2. Notebook 最后一个单元运行 `hello_gpu.submit(...)`，打印一个通关链接（成绩编码在链接的 `#lab=` 片段里）和一串通关码。
3. 读者点链接回到关卡页，或者把通关码粘贴进 `LabCard`；网页按本关规则重新计算星级，并把读者的实测数字和参考数据画在一起。
4. 没有 GPU 的读者可以选「观摩模式」：网页回放档案馆里的真实运行记录，完成关卡但不得星。

详细格式见 `07-notebook.md`。

## 7. 可访问性、设备与性能

- 所有交互都能用键盘完成，焦点可见，图形元素有 `aria-label`（沿用 `ScenePlayer` 的做法）。
- 新手村所有关卡在 375px 宽度下都能完成；手机上的沙盒退化为填空或代码块选择。
- 首屏 JavaScript 压缩后不超过 200 KB；模拟器、代码编辑器、Pyodide 按需加载。
